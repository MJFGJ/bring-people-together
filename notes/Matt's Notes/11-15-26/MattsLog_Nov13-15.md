# MattsLog_Nov13-15

Postit: turning the shared claude.ai artifact prototype into a real app at `/postit`, plus five user tests on the result. 

## 2026-11-13 to 2026-11-15 — Building Postit as a real Next.js app

- **Started from the claude.ai artifact.** Recreated its opening flow — login, then a home screen — as working code at a new `/postit` route in the existing `web/` app, fully isolated from the unrelated Spectrum game at `/` (own layout, own Google Fonts, own CSS module, so nothing leaks between the two).
- **Replaced the "who are you" person-picker with a real sign-in form** (Name / Email / Password — simulated only, nothing is verified or sent anywhere), and replaced the old single-studio home with a **group picker**: you can belong to more than one group, each group posts to its own account and keeps its own members and projects, and you can create a new group or sign out right from that screen.
- **Built out real project creation** (not a stub) and a **group-wide Media tab** — every photo uploaded to any project in a group is visible from one place, with real client-side photo upload (an actual file picker, real thumbnails via `URL.createObjectURL`, no backend).
- **Rebuilt the inside of a project to match the original artifact's post builder** (tray / work-area / preview), with one addition the artifact didn't have: you can pull photos into the post you're building from the group-wide Media library, not just from the current project.
- **Dropped the separate "Drafts" concept** — every project already is a draft until it's posted — and added a real `posted` flag with its own **Posted tab**, plus a **"Request to post"** step ahead of "Mark as posted" (with a Requested badge). Turned Media into a slide-out tray anchored to the icon rail (moved from the right side to the left, next to the rail, after testing), supporting both real HTML5 drag-and-drop onto a project and click-to-add.
- **Split Preview into its own hideable tray** on the right (mirroring the Media tray), and added a full **up/down voting system**: your own vote via explicit buttons, plus clickable simulated-teammate avatars that cycle none → up → down → none, so solo testing can simulate a whole group's reaction. Each photo now shows a live **Approved / Needs vote / Declined** status pill computed from the vote tally — the same spirit as the original artifact's approval view.
- **Found and fixed two real CSS bugs, both the same root cause.** A broad reset rule (`.page button { ... }`, and separately `.page button, .page input { color: inherit }`) used an element selector, which gave it *higher specificity* than every individual button/input's own style class — so no matter what order the CSS was written in, the reset always won. That's what made the Sign-in button render as plain text at first, and later made buttons and the caption box render as white-on-white / dark-on-dark once the background styling was fixed. Both were fixed the same way: rewriting the reset with `:where(...)`, which keeps the reset as a sensible default but gives it zero specificity, so a real component style always overrides it.
- **Caught a layout regression from the new preview tray** during testing: because the tray is a fixed overlay, it doesn't reserve space in the page layout, so it was sitting on top of (and blocking clicks on) the "Mark as posted" and "Add photos" buttons in the project header. Fixed by having the header reserve space for the tray's width whenever it's open.
- Verified the whole build as we went with `tsc --noEmit` and `eslint` (clean throughout), and hands-on in the browser: sign-in → group picker → project builder, drag-and-drop via synthetic drag events, uploading real files, toggling the preview tray, voting and watching the status pill flip live, and the request-to-post flow end to end.
